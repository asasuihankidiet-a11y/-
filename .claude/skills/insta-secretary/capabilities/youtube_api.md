# YouTube連携 — 動画のアップロード

## これは何の道具か

秘書がプログラムからYouTubeへ動画をアップロードできるようにする窓口（API＝サービス同士をつなぐ窓口）。主に `recipes/zoom_archive.md`（Zoom録画の自動アーカイブ）で、録画を限定公開（URLを知っている人だけ見られる公開設定）でYouTubeに保管するために使う。

- **重要: 動画のアップロードは、APIキー（合言葉ひとつの簡易な鍵）では絶対にできない。** OAuth（本人としてログインして許可を渡す仕組み）が必須。本人には「あなたの代わりにあなたのチャンネルへ上げるので、あなた本人の許可が要る方式なんです」と説明する
- API利用そのものは**無料**。ただし1日に使える回数の枠（クォータ）がある — 詳しくは「気をつけること」
- 一度セットアップすれば、以後は本人の操作なしでアップロードできる

始める前に本人へこう説明する:「あなたのYouTubeチャンネルに、秘書が録画を自動で上げられるようにする手続きです。最初だけ15分ほどの画面操作があり、あとは自動です。上げるのは限定公開までで、世に公開するボタンは押しません」

## 準備の手順

手順の流れは `capabilities/google_calendar.md` と同じ。違いは**有効にするAPI**と**権限の範囲**の2点だけ。すでにカレンダー連携でプロジェクト（設定をまとめる箱）を作ってあれば、同じプロジェクトを使い回してよい。画面操作は本人にやってもらい、秘書は1ステップずつ案内する。

1. **プロジェクトを用意する**
   - https://console.cloud.google.com/ にログインし、既存のプロジェクトを選ぶ（なければ `capabilities/google_calendar.md` の手順2のとおり新規作成する）
2. **YouTube Data API v3を有効にする**
   - 左上の三本線メニュー →「APIとサービス」→「ライブラリ」
   - 検索窓に「YouTube Data API v3」と入力し、出てきたカードをクリック →「有効にする」
3. **OAuth同意画面を確認する**
   - まだ設定していなければ `capabilities/google_calendar.md` の手順4〜5のとおり設定する
   - 設定済みなら、公開状態が「テスト」のままで、**テストユーザーに本人のGmailが登録されている**ことだけ確認する
4. **OAuthクライアントIDを用意する**
   - 「APIとサービス」→「認証情報」→「認証情報を作成」→「OAuthクライアントID」→ 種類は**「デスクトップアプリ」**
   - カレンダー連携で作ったものを使い回してもよいが、迷ったら新しく作って用途ごとに分けるほうが管理しやすい
5. **JSONをダウンロードして決めた場所へ置く**
   - 例: `~/secretary/credentials/youtube.json`。置き場所は1か所に固定し、おしごとカードに記録する（`safety.md` ④）
6. **YouTubeチャンネルがあるか確認する**
   - アップロード先のチャンネルがまだ無い場合は、先にYouTubeの画面でチャンネルを作ってもらう（右上のアイコンをクリック →「チャンネルを作成」）
   - チャンネルが複数ある場合は、どのチャンネルに上げるかを本人に選んでもらい、初回承認のときにそのチャンネルでログインしてもらう
7. **初回実行して、ブラウザで承認してもらう**
   - 権限（スコープ＝許可の範囲）は**アップロード専用の `youtube.upload` だけ**を要求する
   - 「このアプリはGoogleで確認されていません」の警告は、自分で作ったアプリなので「続行」で問題ないと伝える
   - 承認が済むと入館証ファイル（トークン）が保存され、以後は自動になる
8. **テストアップロードを必ず1本やる**
   - 数秒の短い動画を「限定公開」指定でアップし、**YouTube側で本当に「限定公開」になっているか**を本人と一緒に確認する
   - 確認は YouTube Studio（自分の動画の管理画面）を開いてもらい、公開設定の欄を見るのが確実
   - ここで「非公開」に固定されていたら、「気をつけること」の審査の話に進む。本番のZoom録画を流すのは、この確認が済んでから（`safety.md` ⑤の「まず小さく試す」）

## 使い方のポイント

- zoom_archiveでは動画を**限定公開**でアップする。「公開」への変更はしない — 世界中に見える状態にするボタンは、必ず本人の手で押してもらう（`safety.md` ①の考え方）
- 権限は `youtube.upload` だけにする。動画の削除やチャンネル設定の変更ができる広い権限は、頼まれても要求しない
- 動画のアップロードはファイルが大きいと時間がかかる。長い録画のときは「いま上げています、あと数分かかりそうです」と途中経過を伝える
- タイトルは後から探しやすい形に揃える（例:「2026-08-28 〇〇講座 第3回」のように日付＋内容）。付け方のルールは最初に本人と決めて、おしごとカードに書いておく
- アップロード成功後は、動画のURLを本人に報告する。元の録画ファイルは消さず、移動と名前の変更まで（`safety.md` ②）
- 本人に説明するときは、専門用語に必ず一言の言い換えを添える（例:「限定公開＝URLを知っている人だけ見られる設定」「クォータ＝1日に使える持ち点」）

## 気をつけること

- **1日の利用枠（クォータ＝1日に使える回数の持ち点）は10,000ユニットで、動画1本のアップロードに約1,600ユニット使う。つまり実質1日6本まで。** 枠は毎日リセットされる（太平洋時間の午前0時＝日本の夕方ごろ）。過去の録画をまとめてアーカイブするときは、1日6本以内に分けて数日がかりの計画を立て、本人にもそう伝える
- **作りたての設定では、アップした動画が「非公開」（本人しか見られない状態）に固定される場合がある。** 「限定公開」を指定しても非公開になるのはこれが原因。Googleに審査（Audit＝この使い方は問題ないですよという確認申請）を出すと解除される。だから手順8のテストアップロードを省略しない。固定されていたら、本人にやさしく説明して審査の申請画面を案内する（申請は無料だが、結果まで日数がかかることがある）
- API利用は無料。枠を使い切っても請求は発生せず、翌日まで待てばまた使える
- 公開状態が「テスト」のままだと入館証（トークン）が約7日で切れることがある。再承認すれば直る — 詳しくは `capabilities/google_calendar.md` の同じ項目を参照
- 大きなファイルのアップロードは途中で失敗することがある。失敗しても元ファイルは残っているので慌てない。同じ動画をやり直す前に、YouTube側に中途半端な動画が残っていないか確認し、二重アップを防ぐ
- JSONと入館証ファイルはチャットに貼らない・共有しない（`safety.md` ④）
- 常駐の仕組みに組み込むときは `capabilities/patrol.md` の見回りをセットにする。アップ失敗が続いたら、まずクォータ切れか、トークン切れか、非公開固定かの順で確かめ、記録を `_patrol/` に残す
- どうしても解決しないときは、止まった手順の番号と画面の文言を確認し、3回直しても動かなければ正直にそう伝えて別のやり方を相談する（`instructions.md` の方針どおり）
