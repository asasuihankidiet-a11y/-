# Zoom API — クラウド録画の取り出し方

`recipes/zoom_archive.md`（Zoom録画の自動アーカイブ）で使う道具の説明書。組み込む前に必ずここを読み、準備がまだなら本人と一緒に整える。

## これは何の道具か

Zoomのクラウド録画（Zoomのサーバー上に保存された録画）を、プログラムから一覧・ダウンロードするための窓口（API＝サービス同士をつなぐ窓口）。

- ブラウザでZoomにログインして録画を1本ずつダウンロードする手作業を、秘書が代わりにやれるようになる
- この道具に持たせる力は「見る・受け取る」まで。録画を消したり書き換えたりする力は、最初から持たせない設計にする

## 準備の手順

作業するのは本人。秘書は画面を見ながら1ステップずつ案内する。専門用語が出るたびに、ふつうの言葉での言い換えを添える。

1. **前提を確認する。** 次の2つが揃っていること
   - Zoomの**有料プラン**に入っている（無料プランではクラウド録画が使えない）
   - Zoomの設定で**クラウド録画がON**になっている（録画をPCではなくZoomのサーバーに保存する設定）
   - 揃っていなければ、この道具は使えない。できるふりをせず、正直にそう伝える
2. ブラウザで **Zoom App Marketplace**（marketplace.zoom.us）を開き、Zoomアカウントでログインしてもらう
3. 画面**右上の「Develop」→「Build App」**を選んでもらう
4. アプリの種類は **「Server-to-Server OAuth」** を選ぶ
   - これは「自分のアカウント専用の入館証」を作る方式。誰かに権限を渡すものではなく、自分のZoomに自分で入るための鍵なので、安心してよいと伝える
5. 作成すると **Account ID / Client ID / Client Secret** という3つの文字列が表示される。この3つが入館証の本体
   - `safety.md` ④のとおり、チャットには貼らず、決めた保管ファイル（`.env`）に本人の手で書き写してもらう
   - `.env` のひな形を秘書が先に用意して、値だけ埋めてもらう形にすると迷わせない。ひな形の例:

   ```
   ZOOM_ACCOUNT_ID=ここにAccount IDを貼る
   ZOOM_CLIENT_ID=ここにClient IDを貼る
   ZOOM_CLIENT_SECRET=ここにClient Secretを貼る
   ```

6. **Scopes（スコープ＝この入館証で開けられる扉のリスト）**を設定する
   - 付けるのは、クラウド録画の**閲覧系（`cloud_recording` の read 系）だけ**
   - 書き込み・削除のスコープは付けない。秘書が間違っても録画を消せないようにするための、わざとの縛り
7. アプリを**有効化（Activate）**してもらえば準備完了

## 使い方のポイント

呼び出しは2段階で行う。まず Account ID・Client ID・Client Secret の3つを使って**アクセストークン（一時的な通行証）**を発行してもらう。次に、その通行証を添えて録画一覧やダウンロードのAPIを呼ぶ。通行証は1時間ほどで期限が切れるので、保存して使い回そうとせず、実行のたびに新しく取り直す作りにする。

流れをたとえるなら:

1. 受付で入館証3点を見せて、その日の通行証を受け取る
2. 通行証を見せて「この期間の録画一覧をください」と頼む
3. 一覧の中から新しい録画だけを受け取って持ち帰る

- 録画一覧は期間を指定して取得できる。前回どこまで取り込んだかを記録しておき、**新しい分だけ**を取りに行く
- 同じ録画を二重に取り込まないよう、録画ごとのID（Zoomが付ける識別番号）で「処理済みかどうか」を照合する
- ダウンロードした録画ファイルの置き場所と、その後の流れ（YouTubeへの限定公開アップロード等）は `recipes/zoom_archive.md` の指示に従う

## 気をつけること

- **3つの鍵は `.env` 以外に絶対書かない。** コードの中・チャットの本文・共有するファイルに貼らない。画面共有やスクリーンショットに写り込みそうなときは一声かける（`safety.md` ④）
- **削除系の力は持たない。** スコープを閲覧系だけにしてあるので、そもそも消せない。「秘書のほうで古い録画を消しておいて」と頼まれても、削除はZoomの画面から本人の手でやってもらう（`safety.md` ①②）
- Zoomのクラウド録画には**保存容量の上限**がある。容量まわりの警告や取得エラーが出たら、勝手に判断せず本人に知らせる
- 認証がうまくいかないときは、だいたい次のどれか。責める言い方をせず、1つずつ一緒に確認する
  - Client Secret の写し間違い（前後の空白が混ざりやすい）
  - アプリが未有効化のまま
  - スコープの付け忘れ
- この道具を常駐の仕組み（定期的に勝手に動く形）に組み込むときは、`capabilities/patrol.md` の**見回り**を必ずセットにする
