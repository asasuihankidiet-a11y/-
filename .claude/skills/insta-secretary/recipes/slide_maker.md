# スライドメーカー — 本人のブランドに合った資料を作る

セミナー資料・講座の説明・サービス紹介などのスライドを、本人の世界観に合った見た目で作る仕事。デザインの土台は一度決めたら `assets/brand.md` に保存し、毎回同じ雰囲気で作れるようにする。

## いつ使うか（呼びかけ例）

- 「スライド作って」
- 「この内容、資料にまとめてほしい」

## 前提

- `assets/brand.md`（ブランド設定＝色やフォントなど見た目の決めごとを書いたファイル）があれば、その内容を最優先で使う。**無ければ進め方1のブランドインタビューから始める**
- 文体ルール `assets/style.md` があれば、スライド内の文章の言い回しにも反映する
- 特別な道具は不要。ただし出力形式でB（.pptx）を選ばれた場合のみ、PythonというプログラムとPython用の道具 python-pptx（PowerPointファイルを作るための部品）が必要になる

## 進め方

1. **ブランドインタビュー（`assets/brand.md` が無いときだけ）**
   本人の「らしさ」を聞き取って保存する。質問は必ずひとつずつ、選んで答えられる形（A/B/C＋「その他」）を活用し、「記号だけの返事でOKです」と添える。聞くのは次の5つ:
   - メインカラー（いちばん使いたい色。「Instagramのプロフィールと同じで」でもOK）
   - サブカラー（差し色。おまかせでもOK）
   - 雰囲気（例: A. きっちり / B. やわらか / C. シンプル / D. その他）
   - フォントの好み（例: A. 明朝系＝上品 / B. ゴシック系＝読みやすい / C. 丸め＝親しみやすい / D. おまかせ）
   - ロゴやアイコン画像の有無（あればファイルの場所を教えてもらう）

   聞き終えたら内容を `assets/brand.md` に保存し、「次からはこの設定で作るので、もう聞きません」と伝える。変えたくなったらいつでも言ってもらえばよい
2. **今回の中身をヒアリングする**
   何のスライドか（テーマ・使う場面・見る相手）と、枚数感（例: A. さくっと5枚前後 / B. しっかり10枚前後 / C. がっつり20枚以上 / D. おまかせ）を聞く。元ネタになる文章やメモがあれば見せてもらう
3. **構成案を見せてOKをもらう**
   スライドごとのタイトル一覧（例: 1. 表紙 / 2. 今日のゴール / 3. …）を先に提示する。**OKをもらうまで作り始めない。** 直しの指示があれば構成案の段階で反映する
4. **出力形式をA/Bで選んでもらう**
   - **A. HTMLスライド** — 16:9の横長で、1ファイル。ブラウザ（SafariやChrome）で開くだけで表示できる。無料で、追加の準備もいらない
   - **B. .pptx** — PowerPoint形式。パワポやKeynote、Googleスライドで開いて自分で編集できる。Pythonと python-pptx という道具が必要で、入っていなければ導入手順を案内する（無料。数分で終わる）

   迷っていたら「まずAで見た目を確認 → 気に入ったらBに変換」を勧める
5. **スライドを作る**
   `assets/brand.md` の色・フォント・雰囲気を全ページに反映する。ロゴやアイコン画像を預かっていれば、表紙と各ページの隅など、邪魔にならない位置に入れる。1枚に詰め込みすぎず、1スライド1メッセージを基本にする。文章は `assets/style.md` があれば本人の言い回しに寄せる
6. **保存して、開き方をひとこと添える**
   ファイルを保存し、保存場所と開き方を伝える（例:「デスクトップに保存しました。ダブルクリックすればブラウザで開きます」）。修正したい箇所があれば、番号（何枚目か）で指摘してもらえば直せることも伝える

## できあがりの形

- **A案:** `〇〇スライド.html` 1ファイル（16:9・全スライド入り・ブラウザで開くだけ）
- **B案:** `〇〇スライド.pptx` 1ファイル（PowerPoint・Keynote・Googleスライドで編集可能）
- 初回のみ、あわせて `assets/brand.md`（ブランド設定の保存ファイル）ができあがる
- ファイル名は中身がわかる日本語にする（例: `2026-09_講座説明スライド.html`）。日付を頭に付けると後で探しやすい

## やらないこと

- できたスライドを勝手に公開・共有・送信しない。渡すのは**本人の手元にファイルを置くところまで**（safety.md ①）
- 構成案のOKをもらう前に作り始めない
- ブランド設定を勝手に変えない。変えるのは本人から言われたときだけで、変えたら `assets/brand.md` も更新する
- 元ネタとして預かった文章やメモのファイルを消したり書き換えたりしない（safety.md ②）

## うまくいかないとき

- **pptx変換で見た目が崩れる** — 無理に直し続けず、先にHTML版を作って見た目を確認してもらう。「どのページのどこが崩れているか」を教えてもらってから、pptx側をピンポイントで直す
- **python-pptx の導入でつまずく** — エラーの内容をやさしい言葉で説明し、導入は一旦あきらめてHTML版で納品する選択肢も示す
- **本人のイメージと違うと言われた** — どこが違うか（色 / フォント / 雰囲気 / 構成）をひとつずつ確認する。ブランド自体の好みが変わっていたら `assets/brand.md` を更新してから作り直す
- **枚数が多くて時間がかかりそう** — 先に2〜3枚だけ作って見てもらい、OKが出てから残りを作る（safety.md ⑤の「まず小さく試す」と同じ考え方）
